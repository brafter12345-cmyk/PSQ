## Scope decision

The integration candidate `3050af5` moved production scoring (frozen fixtures 282 to 372 and
205 to 262). By owner decision, `f7685f7` restores production scoring:

- Missing checkers no longer lose weight in the score. They are still listed and disclosed as
  "not assessed, not measured clean" in the dashboard and PDF coverage notices.
- The single-ASN charge is production's `unique_asns <= 1` again. The measured-ASN change is a
  deferred rate decision (OUTSTANDING item 5s).

Parity on frozen fixtures, production `c0ffe7b` against `f7685f7`, network blocked:

```
finance R10m     282 = 282   0 differing fields
retail R135bn    205 = 205   0 differing fields
vendor estate    205 = 205   31 fields, all insurance.remediation.* ordering (new origin-exposure advice)
ASN-not-collected synthetic fixtures: identical apart from the same remediation fields

```

Fixed-input parity was verified on these recorded fixtures only. Fresh real scans can still differ from the `c0ffe7b` release, because scanner-side measurement and attribution changed (see Known limitations). That effect has not been comprehensively measured.

Add-ons, IntelX settings, deployment flags and credential-export state were not changed.
Server-owned `.env`, `secrets.env`, databases and venvs were excluded from the copy.

## Known limitations

- Scoring code matches production, but scanner-side measurement changes in this release can
  still move real-scan inputs: CDN detection by address range, estate confidence cap, vendor and
  M365 IP attribution and co-tenancy, reverse-DNS forward-confirm demotion, default-certificate
  probe gating and certificate-based lookalike ownership. That effect has not been comprehensively measured.
- `score_reliable` and `confidence_level` now count missing checkers. No score or pricing path
  reads them, but coverage notices can read differently from production.
- Authorised access was verified on the app behind the proxy and by synthetic test client. A
  signed-in browser session through Caddy was not exercised, because staff credentials were not used.
- The server has no Node or pypdf, so the dashboard Node checks and `pdf_snapshot --check` run in
  the workstation gates and the pre-push hook, not on the server.
- Staging copy `/opt/phishield-scanner-staging-f7685f7` and `/tmp/scanner_f7685f7.tar.gz` remain
  on the server until the release is accepted.
- The pre-push hook's Render comment is stale; pushing does not deploy.
- This release record and the DEPLOYMENT.md update are a docs-only follow-up commit after
  `f7685f7`; the deployed code is `f7685f7`.
